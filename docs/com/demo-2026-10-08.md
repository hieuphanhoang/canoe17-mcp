# Gate-3 demo record, 2026-10-08

First end-to-end run of the stdio MCP server with the real COM backend,
driven as an MCP client. Evidence level: **demo_verified**, on a PC with
CANoe 17.6.5 TBE, **no licence** and **no Vector hardware**. Not a bench result.

Scope follows the owner's ASK-002 option (b): licence-free operations only.
Saving and measurement are licence-blocked on this PC (api-evidence C3, M1), so
they are tested against the fake backend and verified later on a licensed PC.

## How it was run

`tests/integration/test_server_live.py` (opt-in, `-m canoe`):

```powershell
$env:CANOE17_MCP_PROBE = "1"
$env:CANOE17_MCP_SANDBOX = "E:\Work\CANoe\sandbox"   # copies of the UDSBasic and Easy samples
uv run pytest tests/integration/test_server_live.py
```

The test starts `python -m canoe17_mcp.server --config <tmp>.toml --backend com`
with `read_only = false` and `allowed_roots = [<sandbox>]`. It talks to the
server through the official MCP client (`mcp.client.stdio`) and writes the full
call transcript to `<sandbox>/demo-transcript.json`. Only copies in the sandbox
were opened or changed; the original samples were not touched.

## What the client saw

Registered tools (10 of 22, filtered by implemented capability and the
`demo_verified` evidence floor): canoe_status, canoe_get_config_summary,
canoe_open_config, canoe_quit, canoe_compile, canoe_measurement,
canoe_operation, canoe_database, canoe_diag_description, canoe_write_window.
No published input schema has a top-level `oneOf`/`anyOf`/`allOf`.
canoe_save_config is not registered: its evidence is `documented` only,
because saving needs the licence.

| Step | Call | Result |
|---|---|---|
| 1 | `canoe_status` | `backend=com`, `connected=false`: status does not attach |
| 2 | `canoe_open_config` path=UDSBasic.cfg, on_dirty=refuse, `confirm=false` | Preview at epoch 0 (not yet connected) |
| 3 | same, `confirm=true` | Attached to the running CANoe, opened the copy; operation completed after OnOpen settled |
| 4 | `canoe_get_config_summary` section=all | Nodes Tester, Test 3, SimDiagECU; `diag:Door` |
| 5 | `canoe_database` list | `[]` (UDSBasic has no databases) |
| 6 | `canoe_write_window` read | Text returned |
| 7 | `canoe_compile` preview, then confirm | `success=true` |
| 8 | `canoe_diag_description` add (copy of the CDD, open_console) preview, then confirm | `diag:Door_1`, qualifier renamed by CANoe (D6), mode `tester`; Diagnostic Console opened |
| 9 | `canoe_diag_description` close_windows `diag:Door_1` all | completed |
| 10 | `canoe_diag_description` remove `diag:Door_1` | completed; list shows only `diag:Door` |
| 11 | `canoe_open_config` on_dirty=discard (the reopen) | Preview showed `configuration_modified=true`, `discards_changes=true`; confirmed; `configuration_modified=false` afterwards |

Every mutation went preview -> confirm with the same arguments, and the
confirmation used the preview's epoch. Compile and later calls ran at epoch 3:
1 on connect, 2 on our Open, 3 on CANoe's OnOpen.

## Found by the demo and fixed

- The open preview reported `launches_canoe=true` although CANoe was running; the
  server would have attached, not launched. The preview now checks for a running
  CANoe process.

## Not covered here

Save and save-copy, `on_dirty=save`, measurement start/stop, test runs and
reports, UDS requests, Tester Present, CAPL calls, signal and system-variable
values, frames: they need a licence (ASK-002 (b)). Configuration edits beyond
diagnostic descriptions are verified at backend level (api-evidence N1-N5,
T3-T4), but the server does not register those tools yet. No physical bus traffic.
